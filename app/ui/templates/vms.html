Add a VM

The image and the XML are uploaded, the guest is written into the inventory as a commit, and the deployment playbook is run. Existing guests are left alone by that run.

It becomes the libvirt domain name and the Pacemaker resource, so it is what every other tool will call this VM.

The image a creation starts from, stored outside git. In a cluster it is imported into the Ceph pool and the guest runs from there afterwards.

Committed with the inventory. A file ending in .j2 is taken as a Jinja2 template and rendered per guest, anything else is used as it is.

    A guest is an entry of the VMs group in the inventory, naming its disk image and its libvirt XML. The image goes in the artefacts, which git does not carry, and the XML is committed with the inventory: both are uploaded from the Inventory page, and a run mounts them under the same root, so the path the entry writes resolves either way. Deploying them is a run of the playbook named above, from the Deployment page.
