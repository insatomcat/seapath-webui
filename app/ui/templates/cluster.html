Read from ha_cluster_exporter on each machine of the inventory, which publishes what crm_mon and corosync-quorumtool said. Every member describes the whole cluster, so the coordinator's answer is the one reported and the line above names it. Standby is crm node standby, run on a cluster member: Pacemaker empties the machine and places nothing there until it is brought back online, which is what an operator does before rebooting a hypervisor. {# Resources: what is running, and where. In SEAPATH most of them are VMs, one Pacemaker resource per guest. #}

Asking each node's exporter

Resource Agent Node Role State Failures
The whole cluster at once. The button on a row is the smaller act.
Location constraints

Where each resource is allowed or asked to run. cli-prefer- is a placement somebody asked for, whether that was preferred_host at deployment or a Move here: the two write the same object and the CIB cannot tell them apart. pin- is pinned_host, which Return does not remove. cli-ban- keeps a resource off a node, which is how an observer is kept from running guests.

Constraint Resource Node Role Score

Pacemaker decides where a resource runs, and this reports the decision. Refresh clears the operation history Pacemaker keeps for one resource, failures included, and asks it to probe the real state again: it is crm resource refresh, run on a cluster member over the connection a convergence uses, under the same lock and in the same run history. Move overrides the decision, with the cli-prefer constraint below: it is the same object preferred_host writes, because vm_manager writes it by running the same command, and it holds the resource until Return puts back what the inventory declares. A guest that is pinned is not offered either, because pinned_host means it runs there or nowhere. A resource whose agent is systemd: is a container the cluster holds, and the Containers page says which quadlet it came from and starts or stops it.
