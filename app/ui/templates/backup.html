Estimated volume

What a full backup exports for every selected guest, at most. A qcow2 is sparse, so this is the data Ceph holds for those disks rather than what they were provisioned at.

Measuring it runs rbd du on the member the backups run on, for the disks of the selected guests only. It walks every object of those disks, which is seconds to tens of seconds, so it is asked for rather than read on every visit. Its figures are deltas, one per snapshot: an image counts what was written since its latest snapshot, so a guest is worth its image and its snapshots added up, bounded by what it provisions. A block rewritten since a snapshot is counted twice there, which is why this is a ceiling and not a measurement.

A local volume

A new partition in the free space after the last partition of a disk, formatted directly or through LVM, and mounted by UUID, by a run of the configure_local_storage role on that machine alone. The run is recorded with the volume it was given; the inventory keeps nothing, since a partition is made once. Nothing that exists is moved, resized or reformatted.

A dedicated key for the backups

Commits three things on cluster_machines: the backup server's host key, a key dedicated to the backups at /root/.ssh/backup_restore_ed25519, and a remote shell that uses it. A run of seapath_setup_backup_restore then generates that key on every member, once, and adds the host key to root's known_hosts.
