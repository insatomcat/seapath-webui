Estimated volume

What a full backup exports for every selected guest, at most. A qcow2 is sparse, so this is the data Ceph holds for those disks rather than what they were provisioned at.

Measuring it runs rbd du, which adds up the objects of every image in the pool. On a cluster holding a dozen guests that is minutes of work for Ceph, so it is asked for rather than read on every visit. Its figures are deltas, one per snapshot: an image counts what was written since its latest snapshot, so a guest is worth its image and its snapshots added up, bounded by what it provisions. A block rewritten since a snapshot is counted twice there, which is why this is a ceiling and not a measurement.

These are the scripts of the upstream backup_restore role, installed in /usr/local/bin by the prerequisites playbook of the machine's distribution. A backup exports every guest's RBD images as qcow2 and rsyncs them to the server; an incremental one exports RBD diffs against the latest snapshot into the same directory. The values below are passed on the command line, so /etc/backup-restore.conf on the machines is untouched and the menu there keeps whatever it was given.
