Held by the cluster, and not declared

Pacemaker runs these units and no quadlet in this inventory describes them. A convergence will not touch them, and a container declared under one of these names would collide with what is already there.

Resource Unit Node State

A container is a quadlet: an entry of upload_extra_files_upload_files putting a .container file in /etc/containers/systemd, with systemctl daemon-reload among the commands that follow the upload. On a cluster, a container Pacemaker runs is a workload of cluster_containers, deployed with its images, its RBD image and its resource by deploy_containers_cluster. The files are committed with the inventory and editable on the Inventory page.

{# The one form on this page. It asks what a quadlet is made of: a name, the file, the machines that receive it, and whether the cluster holds it. Everything else a site writes about a container is in the file. #}

Add a container

The quadlet is committed with the inventory and the entry that uploads it is written into the file. Putting it on the machines is a run, named at the end, and launched from the Deployment page where what it disturbs is written down.

It becomes <name>.container on the machines, the unit <name>.service, and in a cluster the Pacemaker resource. Every other tool will call this container by that name.

The [Container] unit podman reads. A file ending in .j2 is rendered per machine by the upload role, so a quadlet that needs a machine's own address is written as one.

Declares a workload of cluster_containers, which deploy_containers_cluster puts on every hypervisor of the cluster before creating its Pacemaker resource. The cluster then decides which member runs it and restarts it where it fails. Its images, its RBD image and its placement are added in the file afterwards, on the Inventory page. The quadlet must carry no [Install] section: the role refuses one.

The group or the machine the entry is written on. A group whose machines already read that list from somewhere else is refused rather than shadowed: Ansible replaces a variable instead of merging it, so an entry in the wrong place stops the site's other uploads on those machines.

    Install a delivery

    The quadlets, the examples and values.yaml are committed with the inventory, the image archives go to the artefacts, and the workload is declared in cluster_containers. A delivery of a workload already installed replaces it, the form starting from its site values and its placement. The site's configuration files, in site/, are never replaced.
