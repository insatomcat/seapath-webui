Reaching the other machines

A run is Ansible over SSH, and this node reaches only itself until it is given a way to reach the others. Both steps below are deliberate acts, and both are undone in one click.

Site key

The private half of the key the ISO already installed in the ansible account of every machine, the one a conventional control machine holds. This key is root on every machine that trusts it. Uploading it here makes this node as capable as that control machine. It is stored 0600, never sent back out and never logged, and only the fingerprint is displayed. A key protected by a passphrase is refused, because nothing here can type one during a run.

Host keys

Read over the network with ssh-keyscan, which means the answer could come from whoever sits between these machines. Compare each fingerprint against ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub on the machine itself before accepting it. Nothing is written until you do.

The code this node runs

Two things are updated separately here. The playbooks, which are the seapath.ansible collection a run executes, arrive as a file. This service, which is a container image, arrives the way every other change to a machine does: an inventory variable and an apply.

Installed collection

The file is the tarball ansible-galaxy collection build writes, built from the SEAPATH ansible repository. What is installed here seeds from the collection the image ships, so the dependency collections the roles call stay in place. The next run executes it, a run that is already going is left alone, and every run records the fingerprint of what it ran.

This service

The version each machine runs is seapath_webui_image in the inventory. Editing it changes nothing on its own: applying Apply the management UI is what replaces the container, here and on the other machines. That run ends without a final status on this machine, because the service recording it is the service being replaced.
